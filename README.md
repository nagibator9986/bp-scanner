# AI BP Scanner

Платформа сквозного анализа бизнес-процессов подразделений банка: от анкеты и внутренних документов до
BPMN-моделей AS-IS / TO-BE, скоринга, рекомендаций по автоматизации и готовых сценариев n8n.

## Возможности

- **Анкета подразделения** с автосохранением, голосовым вводом и извлечением текста из документов.
- **Документы**: PDF, DOCX (включая таблицы), XLSX, PPTX, TXT, CSV, MD; текст извлекается при загрузке.
- **AI-анализ** в фоне с пошаговым прогрессом:
  1. выявление процессов (шаги, роли, системы, решения, длительность);
  2. BPMN-схемы AS-IS: строятся автоматически, с дорожками по ролям, развилками и циклами доработки;
  3. скоринг по 6 измерениям и индекс потенциала автоматизации (0–100%);
  4. рекомендации по трём категориям: оценка FTE, сроки, KPI;
  5. TO-BE модели с BPMN-схемами;
  6. n8n workflows, которые импортируются в n8n.
- **Дашборд**: топ процессов по потенциалу, профиль оценок, рекомендации и FTE по категориям, распределение
  потенциала, быстрые победы, сравнение подразделений.
- **Отчёты**: Word и PDF с диаграммами.
- **Совместная работа**: доступ к подразделению можно открыть коллегам.
- **Админ-панель**: подключение модели и проверка соединения, редактор промптов с историей версий и тестом,
  база знаний (её материалы попадают в промпты), пользователи и роли, журнал ошибок.

## Архитектура

```
frontend/   React 19 + Tailwind + shadcn/ui, Recharts, bpmn-js; nginx раздаёт статику и проксирует /api
backend/    FastAPI + MongoDB (Motor)
  main.py               точка входа (uvicorn main:app)
  bpscanner/
    app.py              сборка приложения, миграции данных, создание администратора
    config.py           настройки из переменных окружения
    security.py         JWT, роли, проверка доступа к подразделениям
    llm.py              OpenAI-совместимый клиент (Qwen/vLLM и др.), разбор JSON-ответов
    pipeline.py         конвейер анализа (блокировка повторного запуска, «пульс», атомарная замена результатов)
    prompts.py          промпты по умолчанию и подстановка переменных
    normalize.py        нормализация ответов модели
    bpmn.py             генератор BPMN 2.0 XML
    n8n.py              экспорт workflows в формат n8n
    reports.py          отчёты Word / PDF
    analytics.py        аналитика для дашборда
    routes/             HTTP API
  tests/                pytest: модель подменяется поддельным OpenAI-совместимым сервером
```

## Подключение модели

Подходит любая модель с OpenAI-совместимым API (Chat Completions): Qwen за vLLM, SGLang, Ollama, TGI, LiteLLM.
Настройки задаются в интерфейсе («Админ-панель → AI-модель» или «Настройки AI»). Если в интерфейсе они не
сохранены, используются переменные окружения:

| Переменная | Назначение |
|---|---|
| `LLM_BASE_URL` | адрес API, например `http://qwen.internal:8000/v1` |
| `LLM_MODEL` | имя модели на сервере, например `Qwen/Qwen3-32B` |
| `LLM_API_KEY` | ключ, если сервер его требует |
| `LLM_DISABLE_THINKING` | `true` — отключить режим рассуждений Qwen3 (`chat_template_kwargs.enable_thinking=false`) |
| `LLM_JSON_MODE` | `true` — `response_format=json_object`, если сервер поддерживает guided decoding |
| `LLM_MAX_TOKENS`, `LLM_TEMPERATURE` | лимит ответа и температура |
| `LLM_MAX_CONCURRENCY` | сколько запросов к модели выполняется одновременно (по умолчанию 2) |
| `MAX_DOCUMENT_CHARS` | сколько символов документов отправляется в модель (подберите под контекст модели) |

Блоки `<think>…</think>` в ответах вырезаются автоматически. Если модель вернула невалидный JSON, запрос
повторяется с напоминанием о формате. Параметры, которые сервер не поддерживает (`temperature`, `response_format`
и т.д.), автоматически перестают отправляться.

Все переменные бэкенда с описанием — в [`backend/.env.example`](backend/.env.example).

## Запуск

### Docker Compose

```bash
cp backend/.env.example backend/.env   # задайте JWT_SECRET, ADMIN_PASSWORD, LLM_*
docker compose up -d --build
```

Фронтенд будет доступен на http://localhost:3000, API — на http://localhost:8000/api (документация: `/docs`).
Администратор создаётся при первом запуске из `ADMIN_EMAIL` / `ADMIN_PASSWORD`. Если `ADMIN_PASSWORD` не задан,
используется пароль `admin123` и в лог пишется предупреждение — смените его.

### Локальная разработка

```bash
# Бэкенд (нужна MongoDB)
cd backend
python -m venv .venv && . .venv/bin/activate
pip install -r requirements-dev.txt
uvicorn main:app --reload

# Фронтенд: /api проксируется на http://localhost:8000
cd frontend
yarn install
yarn start
```

Для PDF-отчётов нужны системные библиотеки WeasyPrint (Pango) и шрифты с кириллицей: в Docker-образе они уже
установлены, для локального запуска — `apt install libpango-1.0-0 libpangoft2-1.0-0 fonts-dejavu-core`.

### Тесты

```bash
cd backend && pytest
```

Тесты используют MongoDB в памяти (mongomock) и поддельный OpenAI-совместимый сервер, который отвечает как Qwen
(с блоками `<think>`, markdown-обёртками и висячими запятыми). Проверяются авторизация и доступы, загрузка
документов, полный конвейер анализа, экспорт отчётов, BPMN и n8n.

## Деплой (GitLab CI → k8s)

Конвейер в `.gitlab-ci.yml` не менялся. Образ фронтенда берёт адрес бэкенда из переменной `BACKEND_UPSTREAM`.
По умолчанию это `bp-scanner:80`, в `Dockerfile-test` — `bp-scanner-test:80`, как в прежних конфигурациях nginx.

## Безопасность

- Доступ к данным подразделения есть только у владельца, у пользователей, с которыми им поделились, и у администраторов.
- Роль пользователя проверяется по базе при каждом запросе: снятие прав действует сразу.
- Неудачные попытки входа ограничены; заголовки запросов и токены не пишутся в логи.
- В отчётах экранируется весь текст пользователей и модели, а загрузка внешних ресурсов при сборке PDF запрещена.
- Принимаются только файлы допустимых форматов, размер ограничен (`MAX_UPLOAD_MB`).
- Рекомендуется хранить `JWT_SECRET` и `ADMIN_PASSWORD` в секретах k8s, а не в `backend/.env` внутри образа.
